# supabase/ — DB 구축 스크립트

이 폴더의 SQL은 "한 번 실행하고 버리는 스크립트"가 아니라, **새 Supabase 프로젝트를
지금과 같은 상태로 재현하기 위한 구축 정의**입니다. 테이블, RLS 정책, 트리거, 함수가
전부 여기 들어 있습니다. 코드와 마찬가지로 저장소에 보관하고 변경 이력을 남깁니다.

## 새 프로젝트를 세팅할 때 (재해 복구, 리전 이전 등)

Supabase SQL Editor에서 번호 순서대로 전체 실행합니다.

| 순서 | 파일 | 내용 |
|---|---|---|
| 1 | `000_schema.sql` | 테이블 4개 생성 (users, games, events, event_participants) |
| 2 | `001_auth_approval.sql` | 카카오 인증 연결, 가입 승인 체계(status/role), RLS 정책 |
| 3 | `002_host_handover.sql` | 룰마(모임 생성자)가 참석 취소 시 자동 위임 트리거 |
| 4 | `003_integrity.sql` | 중복 참석 방지, 정원 초과/축소 방지 (동시 요청 대비) |
| 5 | `004_kick_user.sql` | 관리자의 유저 추방 함수 |
| 6 | `005_strip_pii.sql` | 카카오 로그인 시 전달되는 개인정보(이메일/이름/프로필사진) 미저장 |

모든 파일은 **재실행해도 안전**하도록 작성되어 있습니다(`if not exists`,
`create or replace`, `drop ... if exists` 패턴). 이미 적용된 DB에 다시 실행해도
데이터를 지우거나 에러를 내지 않습니다.

## 첫 관리자 지정

위 SQL을 전부 실행한 뒤:

1. 앱에서 카카오 로그인 → 가입 요청(닉네임 입력)
2. SQL Editor에서 본인을 승인 + 관리자로 승격

```sql
update users set status = 'approved', role = 'admin'
where nickname = '<본인 닉네임>';
```

## 새 SQL을 추가할 때

- 번호를 이어서(`006_...`) 추가하고, 파일 상단에 목적과 실행 위치를 주석으로 남깁니다.
- 가능하면 재실행해도 안전하게 작성합니다(멱등성). 데이터 삭제처럼 **한 번만 실행해야
  하는 구문**은 이 폴더에 영구 보관하지 말고, 작업 시점에만 실행하고 커밋 메시지나
  대화 기록에 남기는 것으로 충분합니다. (과거 사례: 001에 있던 테스트 데이터 삭제
  구문을 분리한 이유)
- 이 표를 함께 갱신합니다.
