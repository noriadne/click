# 패치노트 인수인계 규칙

이 프로젝트는 여러 PC와 여러 사람/에이전트가 이어서 작업합니다. 현재 상태의 기준은 저장소 루트의 `PATCHNOTES.md`입니다.

- 작업을 시작할 때 `PATCHNOTES.md`를 읽고, 가장 위 버전이 현재 상태라고 간주합니다.
- 사용자가 "다른 곳에서 수정했다"고 하면 `git fetch` 후 `git pull --ff-only`로 맞추고, 새로 올라온 변경을 `PATCHNOTES.md`와 대조합니다. 기록에 없는 변경이 있으면 사용자에게 알리고 항목 추가를 제안합니다.
- 코드, 설정, DB(SQL), 환경변수, 배포 설정을 바꾼 작업이 끝나면 `PATCHNOTES.md` 맨 위(기준선 위)에 다음 버전(`v1.01`, `v1.02` …) 항목을 추가합니다. 양식은 문서 상단에 있습니다. 항목 맨 위에는 이용자에게 그대로 전달할 수 있는 `사용자 안내` 한 줄(~해요 말투, 기술 용어 없이)을 반드시 넣습니다.
- 비밀값(키, 비밀번호, Supabase 프로젝트 ref)은 기록하지 않습니다. 변수 이름과 설정 위치만 적습니다.
- 다른 환경에서 사람이 해야 하는 일(SQL 실행, Vercel 환경변수 변경, 재배포)은 `적용 방법`에 반드시 적습니다.
- 커밋과 푸시는 사용자가 요청할 때만 합니다. 커밋 해시는 푸시 후 알게 되면 해당 항목에 채웁니다.
- `v2.0`처럼 큰 버전은 사용자가 지정할 때만 올립니다.
